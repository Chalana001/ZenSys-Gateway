# 2026-09-21 — M5: reverse proxy

## What was built

**`internal/proxy/`** — a new package, deliberately *not* `internal/routing/proxy.go`
as the plan named it. `routing` must not import `config` or `tenant`, and a proxy that
builds per-product transports from configuration has to import both. Dependency
direction preserved; recorded as an M5 deviation.

- `transport.go` — `deadlineTransport` applies a per-request deadline and hands the
  `cancel` to the body via `cancelOnClose`. The obvious `defer cancel()` is wrong: it
  aborts every streamed response, because `RoundTrip` returns when the *headers* arrive.
  Each route gets its own `http.Transport` (`DisableCompression: true`, `Proxy: nil`).
- `proxy.go` — one `route` per (product, stage), each owning its transport and
  `ReverseProxy`. `Rewrite` calls `SetURL` → `SetXForwarded` → `routing.ApplyForwarded`
  → `pr.Out.Host = pr.In.Host`. `handleError` maps client-cancel (no response),
  body-limit (413), timeout (503 + `Retry-After: 5`), and everything else (502).
- `internal/routing/stage.go` — the §9.1 frontend/backend selector. Whole-segment match,
  case-sensitive.
- Deleted `NotImplementedUpstream`, `ErrNotImplemented`, `WriteNotImplemented`.

## Two defects, both found by running the binary

**1. An oversized body answered `502 upstream_unavailable`, not `413 payload_too_large`.**
`ErrPayloadTooLarge` was declared in `responses.go` and written by nothing. The
`MaxBodyBytes` middleware wrapped the body and left detection to handlers; no handler
read a body until the proxy did. Fixed in two halves, both load-bearing:
- `MaxBodyBytes` refuses a declared `Content-Length` over the limit *before* routing or
  dialling. Disabling this keeps the status at 413 but the upstream gets touched — that
  is exactly what the test asserts.
- `proxy.handleError` maps `*http.MaxBytesError` → 413, for a chunked body that declares
  no length and can only be caught mid-read.

**2. The probe harness could silently measure the wrong process.** `start` waited for
`/readyz` without checking that the process it launched was alive, so when a previous
gateway still held the ports the new one died on
`bind: Only one usage of each socket address` while the old one answered `readyz`. A
whole section reported on a configuration it had never loaded — and it reported a
body-limit that was never applied, which is how defect 1 was found. `start` now waits
for both ports to be free and checks liveness; `stop` waits for the ports to be
released. Same failure shape as M0: a check that passed because it was not looking at
production wiring.

## Two more things worth keeping

- **`kill` on a Windows-native process from Git Bash is a hard kill.** The gateway's
  `shutdown_grace` drain never runs — `a.log` had no shutdown lines at all. So a Git Bash
  harness does *not* exercise graceful shutdown; a clean probe run is not evidence that
  draining works.
- **`statusRecorder.Unwrap` is what makes streaming work.** Go 1.27's `ReverseProxy`
  flushes through `http.NewResponseController`, which unwraps — no `rw.(http.Flusher)`
  assertion anywhere. Removing `Unwrap` makes every streamed response buffer. Pinned by
  `TestProxy_StandardChainExposesFlush`, which fails in 0.01 s with the right message
  rather than letting the 3 s streaming test time out.

## Verification

- **241 top-level tests, 397 subtests, 0 failures under `-race`** (638 `=== RUN` lines).
  16 skip without `ZENSYS_TEST_DSN`; all 16 pass with it.
- Three guards were proved to fail when the thing they guard is broken: `FlushInterval: 0`
  → streaming test fails; removing `Unwrap` → flush test fails; adding `fallback *route`
  to `Proxy` → structural guard fails naming the field.
- `configs/.probe/run.sh` now covers five sections (A trust, B distrust, C proxy,
  E bodies, D outage), asserts every result, and exits non-zero on failure.
- `configs/.probe/upstream/` is a minimal stand-in for `cmd/mockproduct` (M9), which
  should replace it.

## Footgun

The MySQL integration tests `DELETE FROM tenant_routes` in setup, so running them
against the dev database empties the probe's fixtures. The probe's `require_tenant`
guard reports this with the SQL to fix it. Documented in the harness header.
