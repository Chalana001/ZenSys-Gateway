## The five findings worth keeping

**1. `SetInfo` ran *after* the tier-2 check, so a tier-2 refusal had no `tenant` in its
log.** The comment next to the check claimed the opposite, and `WriteRateLimited`'s doc
claimed the tier was "structural rather than conventional" and "cannot drift". It drifted.
Found by the probe (section G), fixed by recording the routing decision as soon as it
exists. `TestTier2RateLimit_RefusalIsDistinguishableInTheLog` pins it, and was observed to
fail — with no other test in the package noticing — when the call was moved back.

**2. The harness's own liveness probe was a client.** `wait_ports_free` checked the public
port with `curl -s -m 1 "$PUBLIC/"`. That is a request like any other: logged, and counted
against tier 1. Section I failed with a 429 where it wanted a 200 because one of its two
tokens had already been spent by the script. Diagnosed by reading the access log and
counting request lines (4 where 3 were intended). Fixed by asking the kernel instead:
`port_listening` uses `/dev/tcp`, which neither logs nor limits and costs no process.
Every section log now begins with the internal `/readyz` rather than a stray public 404.

**3. The harness measured a binary it did not build.** It asserted that
`bin/gateway.exe` *existed* and assumed it was current. After fix 1 was committed, a full
probe run **still** reported the tier-2 refusal with no tenant — the binary was 20 minutes
older than `public.go`. The harness now builds the gateway itself (as it already built its
upstream stand-in) and fails if any `.go` file is newer than the binary. **Existence is not
freshness**, and a check that only proves a file is present reads as coverage while
providing none.

**4. `RetryAfterSeconds` returned 0 for a refusal.** My own test caught it: the guard was
`RetryAfter <= 0` rather than `Allowed`. A refusal admissible within the current second
would carry `Retry-After: 0` — an instruction to spin. Zero is now reserved for the allowed
case.

**5. Three of four attempted guard-breaks did not discriminate on the first try.** See
"Proving guards" below. In two cases the *comment* was wrong rather than the code.

## Proving guards (the rule earned its keep)

M7 attempted four deliberate breaks. Only one failed the test on the first attempt.

- `TestLimiter_EvictsRefilledEntriesBeforeLiveOnes` asserted the **tier** ends with one
  entry. Wrong assertion, not a code bug: eviction is **per shard** by design, so a sweep is
  lazy. Rewrote it to fill every shard, cross the horizon, write to all but one, and assert
  the touched shards end with exactly 1 while the untouched one keeps its 2 — turning the
  lazy scope into an asserted property.
- `TestLimiter_PrefersRefilledEntriesOverLiveOnes` passed under an "evict the newest" break,
  because the sweep always removes the refilled entry first and the forced path never ran.
  Split it: the new `TestLimiter_ForcedEvictionDropsTheStalestLiveEntry` advances only 500 ms
  so nothing refills, and it **does** fail under the break.
- `TestTier1RateLimit_ASpoofedForwardedForCannotEvadeTheLimit` needed **both** defences
  removed before it failed — `SanitizeInbound` *and* keying on `Edge`. The comment now says
  it guards the outcome of two independent mechanisms.
- `TestStandardChain_BodyLimitRunsBeforeTheRateLimiter` discriminates through its **second**
  assertion, not the first: on a first request the bucket is full, so a 429 is impossible in
  either order. The comment now says so.

## Decisions taken

- **§8.1 step 3 before step 4 is settled as "stateless before stateful".** The body limit
  refuses a request on its own terms without spending a token; for a chunked body the
  limiter still refuses before a byte is read, in either order.
- **The limiter's key table is bounded** (`rate_limit.max_entries`, default 4096), which the
  plan did not ask for. Its keys are chosen by whoever is sending requests — the same defect
  class as an unbounded metric label.
- **Rate limiting fails open**, and the Gateway warns at startup when it is disabled: a
  disabled limiter and one silently failing open look identical from outside.
- **The internal listener passes a nil limiter**, deliberately (§8.1 places it in the public
  pipeline; the callers are authenticated loopback services).
- **The 404/403 enumeration consequence was left alone.** M7 was named as the place to
  tighten it. Checked rather than assumed: the listener binds `127.0.0.1`; section F asserts
  `/internal/v1/...` on the public port is proxied to the product; and the statuses are what
  §13.3 specifies, so changing them is a spec change, not a hardening task. Recorded in
  §13.4 and the README, reopened if that listener ever becomes reachable.
- **net/http's header ceiling is `MaxHeaderBytes + 4096`**, above which it answers a bare
  text 431 straight to the connection — before any handler, and **logging nothing** even
  with `ErrorLog` set. Established by measurement with a throwaway probe, then confirmed in
  `net/http/server.go`. An over-long request URI shares the header budget, so it is 431 and
  not 414. Not fixable from inside the process; documented in §17, §21, and the README.
