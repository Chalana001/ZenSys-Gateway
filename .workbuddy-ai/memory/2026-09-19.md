**Design decisions worth keeping:**

## M2 complete — host resolution (§74, §75)

**Packages created:**
- `internal/routing/host.go` — `ParseHost(raw, rootDomain) (Host, error)`. Pure, no HTTP. Six distinct sentinel errors (`ErrEmptyHost`, `ErrMalformedHost`, `ErrIPLiteral`, `ErrIDNHost`, `ErrWrongDomain`, `ErrMultiLabel`) so the log can name the rule that fired while the response stays a uniform 404.
- `internal/routing/resolver.go` — `Resolver.Resolve(slug)`, mapping `tenant.ErrNotFound` → `ErrUnknownTenant`, non-ACTIVE → `ErrTenantDisabled`, anything else → `ErrRegistryDown`. Both sentinels and the cause are kept in the error chain (`fmt.Errorf("%w: %w", ...)`) so the log names the real failure.
- `internal/httpapi/platform.go` — apex landing (`http.FileServer` wrapped in `noDirListing` so a directory without `index.html` 404s instead of listing) and reserved-host 404.
- `internal/httpapi/public.go` — `PublicHandler`, the whole public pipeline; plus `NotImplementedUpstream`, the M5 placeholder, which answers **503 not 404** because by then the tenant has resolved and a 404 would claim the hostname is unregistered.

**Design decisions worth keeping:**
- `ParseHost` deliberately does **not** check reserved hosts or the slug policy. Reserved is a pipeline step *after* multi-label (§65 fixes the ordering); slug shape is `tenant.ValidateSlugFormat`. Each rule keeps exactly one home. Tested explicitly: `admin.zensys.lk` parses to slug `admin`, and `ab.zensys.lk` / `-abc.zensys.lk` parse fine and are rejected later.
- IP literals are checked **twice**, before and after port stripping. `net.SplitHostPort("[::1]")` fails, so checking only afterwards reported a bracketed literal as *malformed* rather than as an address. Found by writing the table test first.
- A non-numeric port is rejected. `net.SplitHostPort` accepts `host:http`; discarding the port anyway is not a reason to accept an invalid authority.
- Empty labels are rejected. Without that check `.zensys.lk` matches the root-domain suffix and yields an *empty* tenant slug.
- The apex handler degrades to 404 if `landing_dir` is missing rather than refusing to start — a cosmetic problem must not become a total outage.

**Two plan claims disproved and corrected (both in `IMPLEMENTATION_PLAN.md` §8.3):**
1. The character allow-list `[a-z0-9.-]` does **not** reject punycode. `xn--mangala-xyz` is spelled entirely in `[a-z0-9-]`. Added an explicit `xn--` rule, and rewrote the claim that one rule covered "punycode/IDN, percent-encoding, and CR/LF".
2. The plan's §8.3 list omitted the empty-label case entirely.

## M3 complete — route cache (§76)

**Files:** `internal/tenant/cache.go` (+ `cache_test.go`), `Service.WithInvalidator` in `internal/tenant/service.go`, `internal/httpapi/isolation_test.go`, `internal/archtest/arch_test.go`. Wiring in `cmd/gateway/main.go` now builds the cache and passes it to the resolver.

**Four refinements beyond the plan, each closing a defect the plan's design permits:**
1. **A registry failure is never cached.** Only `ErrNotFound` is cached; any other error is retried. Caching an outage would serve wrong answers for a whole negative TTL *after* recovery.
2. **The load runs with `context.WithoutCancel` plus an explicit `LoadTimeout`.** `singleflight.Do` runs the load in the first caller's goroutine with that caller's context, so one client disconnecting would fail every request waiting on the same slug. `DoChan` + a detached context fixes it; waiters still give up on their own cancellation via `select`.
3. **The cache is re-checked *inside* the singleflight call.** `singleflight` deletes a key the moment its fn returns, so the window between a cache miss and arrival at `DoChan` is not atomic with the store — a caller that missed just before the previous call finished starts a *second* read. **This was a real bug, caught by a test asserting exactly 1 read and intermittently getting 2.** Re-checking closes it. The same pattern will be needed for any future cache-aside code.
4. **A stale write is discarded via a global invalidation generation counter.** A request that misses reads the registry; the route can change and be invalidated while that read is in flight, and writing the answer anyway serves a dead state for a full TTL. A *global* counter (not per-slug) keeps memory bounded as unknown hostnames are probed; the cost is a wasted cache fill on an unrelated invalidation, never a wrong answer.

**Also decided:** the lifecycle `Service` reads through the repository, **never** the cache — a lifecycle decision must be on the truth, not a copy up to `route_ttl` old. The public path and the lifecycle path deliberately have different consistency needs.

**New guard: `internal/archtest`.** An AST-based test that fails the build if any package-level variable could hold per-request routing state (the `global currentTenant` anti-pattern §31 names). It has its own tests proving the detector bites in both directions — a guard that silently matches nothing is worse than no guard.

**M3 exit criteria — all verified:**
- `-race` isolation test: 60 tenants × 8 concurrent requests (480 requests), every response carrying its own tenant, and **exactly 60 registry reads** (one per tenant, proving singleflight). Plus cold-start (all 360 requests racing a cold cache), Flush-under-load, and mixed active/disabled variants.
- Cache unit tests: cold→warm, negative caching, positive and negative TTL expiry, singleflight keyed by slug, cancelled leader doesn't fail waiters, waiter stops on its own cancellation, stale-write discard, failure-not-cached, capacity refuses to evict live entries, expired-sweep, Flush correctness.
- Service invalidation: all four mutations invalidate; a failed mutation does not.
- **Against real MySQL:** 200 requests for a cached tenant → ~0 registry reads (measured via `SHOW GLOBAL STATUS`); 100 requests for an unknown tenant → 1 read.
- **`negative_ttl` convergence end-to-end:** with `negative_ttl: 2s`, a tenant inserted into MySQL 404'd at t+1s (served from the negative cache) and resolved at t+4s.

**Two more Git Bash traps (both now in the README):**
- **A Windows-native binary cannot read Git Bash's `/tmp`.** `bin/gateway.exe -config /tmp/x.yaml` fails with "The system cannot find the path specified" even though bash can see the file. Put test configs inside the project or use `cygpath -w`.
- **Never `kill` a PID you have not confirmed is alive.** `kill $PID` on an already-exited process can hit a *reused* PID — combined with the `/tmp` trap above (where the gateway exits immediately) this killed the calling shell and aborted the whole script with SIGTERM. Guard with `kill -0 "$PID"` first.

**Test totals after M3:** 189 top-level, 311 subtests, 0 failures, all under `-race`.
