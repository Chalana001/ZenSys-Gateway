# 2026-09-20 — M4: request context and headers (§77, §78)

## What was built

`internal/routing/` gained three files, each with one job:

- **`trusted.go`** — `TrustedProxies`, parsed from `proxy.trusted_proxies` (CIDR or bare IP; empty list is valid and trusts nothing). `config.Validate` now calls `routing.ParseTrustedProxies` instead of keeping its own `parseTrustedProxy`, so the startup check and the request-time reader cannot disagree about what "valid" means.
- **`headers.go`** — `ResolveEdge` (the trust decision), `SanitizeInbound` (delete half of §10.1), `ApplyForwarded` (set half, called by M5's `Rewrite`), `OutboundPolicy`, and `deleteHeader` (case-insensitive, so the §24 invariant does not rest on net/http's key canonicalisation).
- **`context.go`** — request-scoped `Info` (host, tenant, route, `Product()` derived) and `Edge` (proto, host, client IP, trusted), plus the `State` slot.

`internal/httpapi/middleware.go` gained `TrustedProxy`, `RequestState`, and `StandardChain`; `RequestID` now adopts an inbound ID only from a trusted proxy.

## Three decisions that differ from the plan's text

1. **`X-Forwarded-For` is set to the resolved client, not appended.** `ProxyRequest` strips the inbound header before `Rewrite` runs, so appending would re-introduce values the Gateway never verified. Plan §10.1 updated.
2. **The client address is the rightmost *untrusted* entry, not the leftmost.** Every hop appends, so the leftmost entry is whatever the client sent. Reading it would let any client choose its own apparent address — and after M7, its own rate limit. This is the one change that is a genuine security fix rather than a refinement.
3. **`tenant` vs `host_label` in logs.** `rejectRoute` used to log the unvalidated hostname label under the key `tenant`, while the access log uses `tenant` for a resolved canonical slug. A log query for `tenant=X` would have matched hostnames that were never tenants. Renamed in the two cases where nothing resolved.

## The `RequestState` slot, and its one sharp edge

The access log needs the tenant (§15.1), but a value the *handler* writes into a derived context cannot travel back out to a wrapping middleware. So `RequestState` installs a per-request `*routing.State`, the handler fills it in, and both sides read the same pointer.

**Sharp edge: it only works if `RequestState` is the outermost middleware.** The slot is installed by deriving the context, and derivation only travels inward. Anything listed before it in `Chain` reads a context with no slot and sees nothing. `StandardChain` now owns the order for both listeners so the tests exercise what the process runs, and its doc comment states the invariant. `TestHeaderContract_AccessLogCarriesTheRoutingDecision` is the guard: drop `RequestState` and the log silently loses its tenant field.

Two tests pin the boundary from both sides — inside the slot the decision is visible, outside it is not.

## The probe harness

`configs/.probe/run.sh` is the only file. It generates both probe configs from `configs/gateway.dev.yaml` (ports 18080/18081, JSON logs, 2s TTLs) so they cannot drift from what the project ships, then starts the binary twice — trusting and distrusting — and probes it. It reads `ZENSYS_REGISTRY_DSN` from the environment and refuses to run without it rather than carrying a credential literal. Generated files are gitignored; the harness is committed so the claims can be re-checked.

**Every substitution is asserted** (`grep -qF` after the `sed`), because a renamed key in the real config would otherwise turn the probe into a silent copy of the dev config — a run that verifies the wrong thing and reports success. Verified by temporarily changing `route_ttl` in the dev config and confirming the harness refuses to run.

An earlier version had a `make.py` generator that `run.sh` did not call, so the harness depended on files nobody produced and failed at the worst moment. Folding generation into `run.sh` with `sed` removed the dependency; the file was deleted.

It also handles the two Git Bash traps explicitly: `curl -sf URL > /dev/null` rather than `-o /dev/null`, and `kill -0` before every `kill`.
